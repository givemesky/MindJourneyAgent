# 📄 MindJourney 

## MindJourneyAgent 旅游规划智能体

`MindJourneyAgent` 是一款基于**神经符号推理（Neuro-symbolic Reasoning）**与**检索增强生成（RAG）**技术的智能旅游规划系统。该系统通过 **DPI-ME**（基于多维证据融合的动态偏好推理）算法深度感知用户意图，并结合**城市统一知识图谱**自动生成高度定制化、地理科学的旅游行程。

## 2. 核心模块详解
### 2.1 动态偏好推理 (DPI-ME)
系统通过贝叶斯推理框架，在对话过程中动态更新用户的 Consumption（消费）、Interest（兴趣）、Pace（节奏） 三个维度的偏好分布。  
主动收敛：策略层会实时监控画像的信息熵。如果偏好模糊，系统会自动触发 ASK 动作向用户追问。  
神经符号结合：利用 LLM 的语义理解力（神经）提取符号约束，通过数学公式（符号）执行概率更新，确保推理过程透明、可控。  
### 2.2 智能行程规划 (Planner)
不同于传统的文本生成，本系统的规划由算法驱动。  
地理聚类：使用 K-Means 算法根据经纬度将所有打卡点自动分摊到不同天数，确保路线不走回头路。
多策略调度：
硬约束忠实版：严格满足用户选定的餐厅和景点。
兴趣偏好版：根据用户画像自动补全同类型的兴趣点。
消费水平版：根据预算自动寻找图谱邻居中的平价或奢华替代方案。
价格感知：自动计算（门票 + 餐饮）× 人数 + 酒店 × 房间数，给出精确的总预估花销。
### 2.3 共享模型基础设施 (Model Provider)
显存优化：采用单例模式加载基座模型，解决多模块竞争显存的问题。
Adapter 动态切换：
在对话阶段：启用 LoRA，进行高精度的意图识别。
在规划渲染阶段：通过 disable_adapter 临时关闭 LoRA，发挥 Qwen2.5 原生的文学创作能力，生成生动的导游词。

## 3. 工作流说明 (Workflow)
运行 test_chat_rag.py 启动完整任务流：
用户交互：系统通过多轮对话收集信息。
实时画像：DPI-ME 模块在后台根据每一轮对话更新用户画像概率分布。
触发规划：当系统判定偏好已收敛（TERMINATE）时，自动触发 RAG。
图谱检索：retriever.py 根据硬约束（城市、必去点、想吃的菜）在图谱中提取实体。
地理规划：planner.py 按照节奏偏好（Fast/Relaxed）进行地理分天聚类。
报告生成：Qwen2.5 渲染出三套对比方案并保存至 travel_itinerary_report.txt。

user用户与assistant助手的每一轮对话会生成Natural Language Record自然语言记录。
这个自然语言记录会传送到我的dpi_me算法中，算法包括2个板块：
1、第一个板块dpi_likelihood 用于获取维度似然向量。dpi_likelihood里面包含两个组件，第一个是感知与约束提取 (Perception Phase)，通过NL2SL Engine和Constraints Extractor组件来提取符号逻辑约束 (Symbolic Constraints)；第二个是证据映射 (Evidence Mapping Phase) ，通过Evidence Mapper来将刚刚提取的硬约束映射到三个偏好分布。这个板块最后输出的是三个偏好分布的似然向量。
2、第二个板块dpi_reason用于计算偏好置信度与系统熵值评估。dpi_reason里面包含两个组件，第一个是Bayesian Engine，通过贝叶斯更新来进行每轮对话的三个偏好的概率分布；第二个是Entropy Evaluator，计算每轮对话三个偏好分布的信息熵。
dpi_me算法生成三个偏好Consumption (Budget/Luxury)、Interest (Nature/Culture...)、Pace (Fast/Relaxed)的三维度概率分布和信息熵。
最后信息熵可以决定三个偏好是否收敛，若收敛就停止对话。
